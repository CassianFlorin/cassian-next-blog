# Git Config for Multiple Environments

## 🧭 Background Information

When we use Git in various development scenarios, we often encounter conflicts involving identity information:

<Callout emoji="👥">
  At work, you’re required to use your real Chinese name when submitting code,
  but in open-source projects, you might want to use a pseudonym, nickname, or
  the email address associated with your GitHub account as your author
  information.
</Callout>

Manually switching between `user.name` and `user.email` every time is not only a hassle but also prone to errors. Is there a way to automatically switch the Git configuration?

The answer is — yes, use `includeIf`!

---

## ❓ Why is it important to distinguish between Git identities?

Here's how I use it:

- **Company Project Submissions**: Use your Chinese name + company email address
- **Open-Source Project Submissions**: Use your alias `Cassian Florin` + GitHub email address

If you don't need multiple identities, the `--global` configuration is actually all you need:

```bash
git config --global user.email "公司邮箱"
git config --global user.name "中文名"

git config --global pull.rebase true
```

## 🧬 A More Flexible Multi-Identity Configuration Solution (Recommended)

### ✍️ Description of My Development Environment

- macOS 15.4.1 (M1 Pro)
- JetBrains Toolbox suite (CLion, WebStorm, DataGrip)
- Git is installed system-wide
- The article directory structure uses `~/dev/` as the root directory

---

### 📁 Create an additional Git configuration file

1. Open the terminal and navigate to the user's home directory:

```bash
cd ~
ls -a
```

2. Create a new Git configuration file:

```bash
vim .gitconfig_qnvip
```

Sample content:

```ini
[user]
    name = Cassian Florin
    email = your-open-source-email@example.com
```

You can also use `touch .gitconfig_qnvip` to create an empty file first and then edit it.

---

### 🔁 Modify the main file `.gitconfig` to implement conditional switching

Edit `~/.gitconfig` and add the following configuration:

```ini
[user]
    name = 中文名
    email = 公司邮箱

[core]
    autocrlf = input

[pull]
    rebase = true

[includeIf "gitdir:/Users/huapai/dev/open/"]
    path = /Users/huapai/.gitconfig_qnvip
```

<Callout emoji="🧠" type="info">
  `includeIf` checks whether the path prefix matches. If you enter any
  repository under `/Users/huapai/dev/open/` , Git will automatically load the
  specified configuration file. Of course, the reverse is also true—you can use
  open-source projects as your default configuration. For your company, use
</Callout>
under the optional directory.

---

## 🧪 Live Demo

Initialize a new project in the `~/dev/open/` directory:

```bash
mkdir ~/dev/open/test-project
cd ~/dev/open/test-project
git init
```

View the currently active Git configuration:

```bash
git config user.name
git config user.email
```

If "`Cassian Florin`" and your open-source email address are displayed, it means `includeIf` is now active!

---

## ✅ Summary & Recommendations

- Developers with a single identity can simply use the global configuration.
- For company, open-source, or multiple roles, we recommend using `includeIf` to manage multiple identities.
- Later on, you can also write automation scripts, switch identities with a single click, and use it in conjunction with Git hooks, among other things.
