# Git Config Setup for Multiple Environments

## 🧭 Background

When using Git across multiple development scenarios, we often encounter conflicts regarding identity information:

<Callout emoji="👥">
At work, code commits require the use of your real Chinese name, whereas in open-source projects, you might want to use a pseudonym, nickname, or your GitHub
  -linked email as your author information.

</Callout>

Manually switching between `user.name`
and `user.email`
every time is not only cumbersome but also prone to errors. Is there a way to automatically switch Git configurations?

The answer is—yes, using `includeIf`
!

---

## ❓ Why Distinguish Between Git Identity Configurations?

Here’s how I use it personally:

- **Company project commits**: Use my Chinese name + company email
- **Open-source project commits**: Use my alias `Cassian Florin`

* GitHub email

If you don’t need to manage multiple identities, the `--global`
configuration is actually sufficient:

```bash
git config --global user.email "公司邮箱"
git config --global user.name "中文名"

git config --global pull.rebase true
```

### 📁 Create an Additional Git Configuration File

1. Open Terminal and navigate to your home directory:

```bash
cd ~
ls -a
```

2. Create a new Git configuration file:

```bash
vim .gitconfig_qnvip
```

Sample content:

```ini
[user]
    name = Cassian Florin
    email = your-open-source-email@example.com
```

You can also use `touch .gitconfig_qnvip`
to create an empty file first and then edit it.

---

### 🔁 Modify the `.gitconfig`

main file to enable conditional switching

Edit `~/.gitconfig`
and add the following configuration:

```ini
[user]
    name = 中文名
    email = 公司邮箱

[core]
    autocrlf = input

[pull]
    rebase = true

[includeIf "gitdir:/Users/huapai/dev/open/"]
    path = /Users/huapai/.gitconfig_qnvip
```

<Callout emoji="🧠" type="info">

`includeIf`
will check if the path prefix matches; if you enter any repository under `/Users/huapai/dev/open/`
, Git will automatically load the specified configuration file.
Of course, the reverse is also true—you can set open-source projects as your default configuration. Company repositories under the optional directory

</Callout>

## 🧪 Practical Demo

Initialize a new project in the `~/dev/open/`
directory:

```bash
mkdir ~/dev/open/test-project
cd ~/dev/open/test-project
git init
```

View the currently active Git configuration:

```bash
git config user.name
git config user.email
```

If `Cassian Florin`
and your open-source email address are displayed, it means `includeIf`
is active!

---

## ✅ Summary & Recommendations

- If you’re a developer with only one identity, using global configuration is sufficient.
- If you have company, open-source, or multiple roles, we recommend using `includeIf`
  to manage multiple identities.
- Later on, you can also write automation scripts, switch identities with a single click, or use Git hooks in conjunction with this setup.
