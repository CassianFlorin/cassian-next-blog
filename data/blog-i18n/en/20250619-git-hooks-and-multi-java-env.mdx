# Resolving Issues with Git Hooks in Multi-JDK Environments

## 🧠 Cause

Our company uses a Git commit hook to perform pre-commit validation on the commit content and code before a Git commit is made.
I have multiple JDK versions installed locally, with the latest being JDK 22. As a result, I encountered execution failures when using the Spotless plugin with Maven.

## ⚙️ Install the Required JDK

### Check Available Java Versions

Run the following command to view the Java versions currently available:

```bash
sdk list java
```

### Install the JDK Required for Your Project

This environment currently uses JDK 8. Once you’ve identified the required version, run:

```bash
sdk install java 8.0.452-amzn
```

### Verify the Installation

After installation, verify the Java version:

```bash
java -version
```

Expected output:


## 🔧 Configure SDKMAN in the Project

### Project Directory Structure

Assume the project directory structure is as follows:

```plaintext
your-project/
├── .husky/
│   └── pre-commit
├── .sdkmanrc # sdkman配置
├── mvnw
├── mvnw.cmd
├── pom.xml
├── package.json
├── lint-staged.config.js
└── ...
```

### Create the .sdkmanrc Configuration File

Create the `.sdkmanrc`
file in the project root directory and enter the JDK information:

```plaintext
# This file is used by SDKMAN to automatically switch to the correct Java version
# when entering this project directory
#
# 注意：
# 1. 此文件需要 SDKMAN 支持才能生效
# 2. 如果您没有安装 SDKMAN，请参考 [SDKMAN 安装与配置指南](/blog/20250619-install-sdkman)
# 3. Windows 用户需要在 Git Bash 或类似的 Unix-like 环境中使用 SDKMAN
# 4. 如果您使用的是 IDE（如 IntelliJ IDEA），请确保在项目设置中也配置了正确的 JDK
#
# Note:
# 1. This file requires SDKMAN to take effect
# 2. If you haven't installed SDKMAN, please refer to the installation guide
# 3. Windows users need to use SDKMAN in Git Bash or similar Unix-like environment
# 4. If you're using an IDE (like IntelliJ IDEA), make sure to configure the correct JDK in project settings

java=8.0.452-amzn
```

## 🔧 Configure the pre-commit Hook

### Complete pre-commit Script

Here is a complete pre-commit configuration file that supports cross-platform use:

```bash
#!/bin/sh
# Check if running on Windows or Unix-like system
case "$(uname -s)" in
  MINGW*|MSYS*|CYGWIN*)
    # Windows environment
    IS_WINDOWS=true
    SDKMAN_DIR="$USERPROFILE/.sdkman"
    SDKMAN_INIT="$SDKMAN_DIR/bin/sdkman-init.sh"
    ;;
  *)
    # Unix-like environment (macOS, Linux, etc.)
    IS_WINDOWS=false
    SDKMAN_DIR="$HOME/.sdkman"
    SDKMAN_INIT="$SDKMAN_DIR/bin/sdkman-init.sh"
    ;;
esac

# Check if .sdkmanrc file exists and SDKMAN is installed
if [ -f .sdkmanrc ] && [ -f "$SDKMAN_INIT" ]; then
  echo "SDKMAN detected, activating project Java version"
  # Load sdkman
  source "$SDKMAN_INIT"

  # Execute sdkman commands
  sdk env
else
  echo "SDKMAN not detected or .sdkmanrc not found. Using system Java version."
  # Print current Java version for reference
  if command -v java >/dev/null 2>&1; then
    echo "Current Java version: $(java -version 2>&1 | head -n 1)"
  else
    echo "Warning: Java not found in PATH"
  fi
fi

# Execute other pre-commit hooks
if [ -f "$HOME"/qnvip.gitconfig.sh ]; then
  bash "$HOME"/qnvip.gitconfig.sh
fi

npx --no-install node .husky/scripts/modify-author-from-file.js
npx lint-staged --verbose --debug
```

### Script Functionality Description

<Callout emoji="🔍">
The main functions of this script are: 1. **Cross-platform Detection**: Automatically identifies Windows and Unix-like systems 2.
  **SDKMAN Integration**: Automatically loads SDKMAN and switches to the project’s specified Java version 3. **Error Handling**:
  Displays the current Java version information when SDKMAN is unavailable 4. **Additional Hooks**: Executes extra Git
  hooks and code checks

</Callout>
