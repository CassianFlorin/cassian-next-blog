# What Is Obsidian: From Installation to Opening the Knowledge Base via the Command Line

If this is your first time hearing about Obsidian, don't overcomplicate it at first.

It is essentially a note-taking tool used to manage local Markdown files. Each note you write is typically a file named `.md` on your computer; these files are stored in a regular folder, which Obsidian refers to as a “Vault.”

So Obsidian didn't start out as "just another cloud-based note-taking app," but rather as a knowledge base that more closely resembles a file system: content is stored locally, the format is open, directories are visible to the user, and notes can be linked to one another.

## What Problems Does Obsidian Solve?

Standard note-taking apps typically emphasize recording: whatever comes to mind today, just write it down. Obsidian is better suited for long-term accumulation: the content you write down today can still be searched, linked, organized, and reused in the future.

It has several key features.

First, **notes are local files**. Your knowledge isn't stored solely in the database of some online service—it's stored in a folder on your own computer. You can back them up, sync them, and migrate them, and you can also open them with other editors.

Second, **the format is Markdown**. Markdown is a very lightweight text format that is suitable for both human reading and machine processing. Headings, lists, code blocks, citations, and links can all be expressed using plain text.

Third, **notes can be linked to one another**. In Obsidian, typing "`[[项目复盘]]`" will link to another note. Over time, instead of ending up with a collection of isolated documents, you’ll build an interconnected network of knowledge.

Fourth, **it works well with automation tools**. Since notes are essentially files, scripts, agents, and command-line tools can all read and write this content. This is also why it’s well-suited to serve as the foundation for a personal knowledge base.

## A Few Basic Concepts

Understanding a few terms before you begin the installation will make the process much easier.

### Vault

Vault is an entire knowledge base managed by Obsidian. You can think of it as a regular folder, for example:

```text
我的知识库/
├── 工作/
├── 学习/
├── 项目/
└── 日记/
```

Obsidian doesn't open a specific note; it opens the entire Vault. A user can have multiple Vaults, but it's recommended to start with just one.

### Note

A "Note" is a note entry, which typically corresponds to a file named `.md`.

For example, if you create a note in Obsidian named `什么是 Agent`, you'll typically see the following in the file system:

```text
什么是 Agent.md
```

This is important: Obsidian doesn't lock your content into some weird format.

### Link

A "Link" is a connection between notes.

```markdown
这篇文章和 [[Agent 与 Obsidian 工作流]] 有关。
```

When you click this link, Obsidian will open the corresponding note. If the note doesn't exist yet, you can create it right away.

### Graph View

Graph View is Obsidian's graph view. It represents notes as nodes and links as lines.

Many people are initially drawn to Obsidian because of its mind maps, but the mind maps aren’t the core feature. What’s truly valuable is the connections you actively create while taking notes; the mind maps are simply a visual representation of those connections.

## Installing Obsidian

The safest way is to download it from the Obsidian website:

[https://obsidian.md/download](https://obsidian.md/download)

Select your system version:

- macOS: Download `.dmg` and drag it to the Applications folder.
- Windows: Download the installer and follow the installation wizard to complete the installation.
- Linux: Choose the appropriate format—AppImage, deb, rpm, or another format—based on your distribution.

Once the installation is complete, open Obsidian. The first time you launch it, you'll be prompted to choose between creating a new Vault or opening an existing folder.

If you're a new user, we recommend creating a new Vault.

## Creating Your First Vault

I suggest not designing a complex directory structure at first; just set up a structure that works.

For example, create a Vault named:

```text
My Knowledge Base
```

Then create a few directories inside it:

```text
Inbox/
Projects/
Knowledge/
Outputs/
```

These four directories are enough to get started:

- `Inbox`: Temporary notes; place content here that hasn’t been organized yet.
- `Projects`: Project processes, meeting minutes, and troubleshooting records.
- `Knowledge`: Concepts, methods, and lessons learned for long-term reuse.
- `Outputs`: Content to be published as blog posts, documents, or proposals.

Your table of contents doesn't have to be perfect from the start. The great thing about Obsidian is that it's essentially a folder, so you can adjust it at any time later on.

## Writing My First Note

First, create a very simple note, such as:

```text
我的第一篇 Obsidian 笔记
```

Here's how you can write the content:

```markdown
# 我的第一篇 Obsidian 笔记

今天开始用 Obsidian 管理自己的知识库。

## 我想解决的问题

- 不想让有价值的讨论只留在聊天记录里。
- 希望项目经验下次还能被找回来。
- 希望长期积累可以变成文章、文档或方案。

## 相关笔记

- [[个人知识管理]]
- [[Agent 与 Obsidian 工作流]]
```

By now, you've already used Obsidian's core features: Markdown, files, and links.

## What Is the Obsidian CLI?

The desktop version of Obsidian is primarily designed for human use: open the app, edit notes, search for content, and view links.

CLI, on the other hand, is designed for command-line and automation scenarios: reading, creating, and searching for notes, as well as appending content, all from the terminal. This allows agents or scripts to collaborate with your knowledge base.

One thing to note: Obsidian supports two common automation methods.

The first type is the `obsidian://` URI. It can be used to open Vault, open a note, create a note, or trigger a search via a link, making it suitable for cross-app interactions.

The second option is the Obsidian CLI, which involves using the `obsidian` command in the terminal. It is suitable for scripts, agents, and more complex automation workflows.

To enable the CLI, first make sure you have a recent version of the Obsidian desktop app installed, and then open the following in Obsidian:

```text
Settings -> General -> Command line interface
```

Once enabled, follow the on-screen prompts to add the CLI to your system PATH. After adding it, restart the terminal.

On macOS, this entry is typically created after registration:

```bash
/usr/local/bin/obsidian
```

On Windows, the installer provides a terminal forwarding entry; on Linux, the CLI is typically placed in `~/.local/bin/obsidian`, and you need to verify that `~/.local/bin` is already in `PATH`.

You can start by checking:

```bash
command -v obsidian
obsidian help
```

If `command -v obsidian` does not produce any output, you can also check:

```bash
ls -l /usr/local/bin/obsidian
/usr/local/bin/obsidian help
```

If none of these commands exist, it means your system does not yet have a directly executable Obsidian CLI. In this case, first make sure the desktop version of Obsidian is properly installed and running, then go back to Settings to enable and register the CLI.

Additionally, the Obsidian app must be running when you execute CLI commands.

## Viewing Vault Using the CLI

Once the CLI is up and running, you can start by checking which commands are available:

```bash
obsidian help
```

If you have multiple Vaults, you can specify the Vault name:

```bash
obsidian vault="My Knowledge Base" files
```

After listing the files, you can read a specific note:

```bash
obsidian vault="My Knowledge Base" read path="Knowledge/个人知识管理.md"
```

You can also view information about a specific file:

```bash
obsidian vault="My Knowledge Base" file path="Knowledge/个人知识管理.md"
```

There are two common parameters here that need to be distinguished:

- `file=` More like searching by note name, similar to the wikilink experience in Obsidian.
- `path=` This is the exact file path, suitable for use with scripts and Agents.

In an automated scenario, I would recommend using `path=` because it is clearer.

## Creating and Appending Notes Using the CLI

Create a new note:

```bash
obsidian vault="My Knowledge Base" create path="Inbox/今天的想法.md" content="今天开始整理 Obsidian 工作流。"
```

Add content to an existing note:

```bash
obsidian vault="My Knowledge Base" append path="Inbox/今天的想法.md" content="\n\n## 后续行动\n\n- 整理目录结构\n- 建立第一组链接"
```

Read Validation:

```bash
obsidian vault="My Knowledge Base" read path="Inbox/今天的想法.md"
```

When combined, these three commands form the smallest command-line loop: create, append, and read.

## Searching Notes Using the CLI

As the Vault grows, search becomes increasingly important.

```bash
obsidian vault="My Knowledge Base" search query="Agent"
```

If you want the Agent to help you find historical context, you can usually have it search first, then read the relevant notes, and finally summarize the existing conclusions.

This process is much more reliable than simply relying on chat logs, because the knowledge is stored in a place where you can view, edit, and verify it.

## Recommended Order for Getting Started

If this is your first time using Obsidian, I recommend following these steps in this order:

1. Install the desktop version of Obsidian.
2. Create a Vault.
3. Write your first Markdown note.
4. Learn how to create links using `[[笔记名]]`.
5. Verify whether `obsidian help` runs on your machine.
6. Use the CLI to create, read, and search for a note.
7. Then consider using the Agent to help organize and reuse your notes.

Don't install too many plugins right from the start, and don't design a complex categorization system right away. First, go through the entire process of entering, organizing, saving, and reusing a single piece of real data.
