# Git Hooks and Node Environment Issues

## 🧠Cause

I previously resolved the issue described in [Git Hooks and Multi-JDK Environment Issues](/blog/20250619-git-hooks-and-multi-java-env). However, today I encountered another problem where the local Node environment 🪝 hooks were not being recognized. It really has been a series of setbacks.

<Callout emoji="📖">
If you haven’t yet read the solution to the JDK environment issue, I recommend first checking out [Git Hooks and Multi-JDK Environment Issues](/blog/20250619-git-hooks-and-multi-java-env)
  to learn how to manage Java environments using SDKMAN.

</Callout>

Judging from the shell log above, Git hooks can no longer detect my Node environment. Additionally, the `node_modules` folder installed via `npm install` in the project does not contain the `npx` executable.

## ❌ Problem

My development computer is a MacBook Pro with an M1 Pro chip. For developers new to the Mac system, when setting up their own shell environment on a new computer, I imagine some of you will use Homebrew, just like I did.
I have to admit that installing packages this way is indeed convenient—all it takes is `brew install xxx`. However, this can also lead to environment mismatch issues.

Before writing this document, my shell environment consisted entirely of packages installed via Homebrew.
Specifically, the files installed via `brew install` are placed in the `/opt/homebrew/bin/` directory, which differs from where the native environment actually reads them.
Most Linux and Unix developers use directories like `/usr/bin` and `/usr/sbin` to access the executables they need, and this differs significantly from actual production environments.

## 📝 Summary

Through resolving this issue, I’ve summarized some important lessons regarding development environment management:

### 🔄 Choosing an Environment Management Tool

1. **Avoid using Homebrew to install development language environments**: Although Homebrew is convenient, it can cause path inconsistencies that interfere with the proper functioning of Git hooks
2. **Use version management tools**:
   - Java environment: Manage using [SDKMAN](/blog/20250619-git-hooks-and-multi-java-env)
   - Node.js environment: Manage using NVM
   - Python environment: Manage using pyenv

### 🔗 Related Articles

- [Git Hooks and Multi-JDK Environment Issues](/blog/20250619-git-hooks-and-multi-java-env) - Resolving Java environment issues
- [SDKMAN Installation and Configuration Guide](/blog/20250619-install-sdkman) - Detailed installation tutorial for SDKMAN

### 💡 Best Practices

1. **Unified Environment Management**: Use the same environment management tool consistently across the team
2. **Project Configuration**: Add the appropriate configuration files to the project (e.g., `.sdkmanrc`
   , `.nvmrc`
   )
3. **Documentation**: Document the environment setup steps in the project documentation so team members can quickly set up their environments

This way, whether the issue involves a Java or Node.js environment, it can be properly resolved, ensuring that Git hooks function correctly.
