# Git Hooks and Node Environment Issues

## 🧠The Cause

I had previously resolved the issue described in [Git Hooks and Multi-JDK Environment Issues](/blog/20250619-git-hooks-and-multi-java-env). But today, the hooks in my local Node environment 🪝 aren't being recognized again. It really is a case of one setback after another.

Based on the shell logs above, the Git hook cannot access my Node.js environment. Additionally, there is no npx executable file in the `node_modules` folder installed via `npm install` in the project.

## ❌ Issues

My development computer is a MacBook Pro with the M1 Pro chip. For students new to Mac development who are setting up their own shell environment on their computers, I imagine some of you will use Homebrew, just like I do.
I have to say, installing packages with Homebrew is indeed convenient—all you need to do is run `brew install xxx`. However, this can also lead to environment compatibility issues.

Before writing this document, my shell environment relied entirely on packages installed via `brew`.
The specific issue is that files installed via `brew install` are placed in the `/opt/homebrew/bin/` directory, which differs from how the native environment actually accesses them.
Most Linux and Unix developers use directories such as `/usr/bin` and `/usr/sbin` to locate the executables they need, which differs significantly from actual production environments.

## 📝 Summary

Through resolving this issue, I have gained some important insights regarding development environment management:

### 🔄 Selecting Environmental Management Tools

1. **Avoid using Homebrew to install development environments**: Although Homebrew is convenient to use, it can cause path inconsistencies that interfere with the proper functioning of Git hooks
2. **We recommend using version management tools**:
   - Java environment: Use [SDKMAN](/blog/20250619-git-hooks-and-multi-java-env) for management
   - Node.js environment: Use NVM for management
   - Python environment: Use pyenv for management

### 🔗 Related Articles

- [Git Hooks and Solutions for Multi-JDK Environments](/blog/20250619-git-hooks-and-multi-java-env) - Resolving Java Environment Issues
- [SDKMAN Installation and Configuration Guide](/blog/20250619-install-sdkman) - Detailed Installation Tutorial for SDKMAN

### 💡 Best Practices

1. **Standardized Environment Management**: Use the same environment management tool consistently across the team
2. **Project Configuration**: Add the appropriate configuration files to the project (e.g., `.sdkmanrc`, `.nvmrc`)
3. **Documentation**: Document the environment setup steps in the project documentation so that team members can quickly set up their environments

This way, any issues with either the Java or Node.js environment can be properly resolved, ensuring that Git hooks work as intended.
