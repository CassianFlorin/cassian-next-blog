# SDKMAN Installation and Configuration Guide

## 🧠 What is SDKMAN?

SDKMAN is a tool for managing multiple versions of software development kits, particularly different versions of Java. It allows you to easily switch between different JDK versions across projects.

<Callout emoji="💡">
SDKMAN supports not only Java but also Kotlin, Scala, Gradle, Maven, and many other development tools.

</Callout>
## 🎯 Why Do You Need SDKMAN?

During development, we often need to work on multiple projects, each of which may use a different version of Java. SDKMAN helps us:

- 🔄 **Easily switch between Java versions**
- 🛠️ **Unify the team’s development environment**
- 🚀 **Simplify tool installation and management**
- 🔧 **Resolve version conflicts in Git Hooks**

<Callout emoji="📖">
If you’re experiencing issues with Git Hooks and multi-JDK environments, check out our other article: [Resolving Git Hooks and Multi-JDK Environment Issues](/blog/20250619-git-hooks-and-multi-java-env)

</Callout>

## 📦 Installing the Java Version Required for the Project

This project uses Java 8. After installing SDKMAN, run the following commands to install the required Java version:

```bash
sdk install java 8.0.452-amzn
```

### View available Java versions

```bash
sdk list java
```

### View installed versions

```bash
sdk list java | grep installed
```

### Common SDKMAN Commands

| Command | Description |
| ------- | ----------- |

| `sdk list java`
| View all available Java versions |
| `sdk install java <version>`
| Install a specific Java version |
| `sdk use java <version>`
| Temporarily switch to a specific version |
| `sdk default java <version>`
| Set the default Java version |
| `sdk current java`
| View the currently used Java version |
| `sdk uninstall java <version>`
| Uninstall a specific Java version |

## ✅ Verify Installation

After installation, you can run the following commands to verify that SDKMAN is working properly:

```bash
sdk version
```

Verify that the Java version is correct:

```bash
java -version
```

The expected output should look like this:

```bash
openjdk version "1.8.0_452"
OpenJDK Runtime Environment (build 1.8.0_452-b08)
OpenJDK 64-Bit Server VM (build 25.452-b08, mixed mode)
```

## 🔄 Automatic Java Version Switching for Projects

This project includes a `.sdkmanrc`
file that automatically switches to the correct Java version when you enter the project directory. To enable this feature, run:

```bash
sdk env
```

### Example Project Configuration File

Create a `.sdkmanrc`
file in the project root directory:

```plaintext
# This file is used by SDKMAN to automatically switch to the correct Java version
# when entering this project directory
#
# 注意：
# 1. 此文件需要 SDKMAN 支持才能生效
# 2. 如果您没有安装 SDKMAN，请参考本文档进行安装
# 3. Windows 用户需要在 Git Bash 或类似的 Unix-like 环境中使用 SDKMAN
# 4. 如果您使用的是 IDE（如 IntelliJ IDEA），请确保在项目设置中也配置了正确的 JDK

java=8.0.452-amzn
```

## 🔧 Troubleshooting

### Java Version Issues with Git Hooks

If you encounter Java version-related issues when running Git commands, please ensure:

1. ✅ SDKMAN is installed correctly
2. ✅ The Java version required by the project is installed
3. ✅ SDKMAN has been loaded in your shell configuration file (such as `.bashrc`
   , `.zshrc`
   , or `.bash_profile`
   for Git Bash)

<Callout emoji="💡">
If you do not have SDKMAN installed, Git hooks will use the system’s default Java version. Please ensure your system’s
  Java version is compatible with the project.

</Callout>

### Windows-Specific Issues

On Windows, if you use Git in CMD or PowerShell, you may need to manually set the `JAVA_HOME`
environment variable to point to the correct Java version.

#### Set the JAVA_HOME Environment Variable

```powershell
# PowerShell 示例
$env:JAVA_HOME = "C:\Users\YourUsername\.sdkman\candidates\java\8.0.452-amzn"
```

#### Set the Environment Variable Permanently

```powershell
# 设置系统环境变量（需要管理员权限）
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Users\YourUsername\.sdkman\candidates\java\8.0.452-amzn", "User")
```
